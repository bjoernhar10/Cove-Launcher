# Cove: Notes for Claude

Cove is a universal desktop game launcher for Linux (x86_64, ARM64), Windows (x64) and macOS (Apple Silicon, Intel).
It brings games from every store and local games together in one calm, tidy library.
Architecture details: `docs/architecture.md`.

## Languages and roles

| Area | Language | Location | Role |
|---|---|---|---|
| Core | **Rust** (Tauri 2) | `apps/desktop/src-tauri` | Library, game launching, process/sidecar management, plugin host, the only bridge to the UI |
| UI | **TypeScript** + React + Vite | `apps/desktop/src` | Interface; talks to the core only through Tauri commands |
| Plugins | **JavaScript** (ES modules, no build) | `plugins/` | Third-party extensions |
| Store connectors & achievements | **C#** .NET 9, Native AOT | `services/connectors` | Steam/GOG/Epic/… integration, achievements |
| Recommendations | **Python** 3.12 (uv, numpy, scikit-learn) | `services/recommender` | Local hybrid recommender, Tauri sidecar (PyInstaller binary) |
| Catalogue proxy | **TypeScript** (Cloudflare Worker, Hono, zod) | `services/catalog-proxy` | Fixed API in front of IGDB so users need no keys; holds the IGDB secrets |
| Shared contracts | TypeScript + JSON Schema | `packages/shared` | Types and schemas for **all** RPC messages |

**Communication:** JSON-RPC 2.0 over stdio, one JSON message per line. stdout is for RPC only, logs go to stderr.
When you add or change an RPC method, update **in the same step**:
the TS types (`packages/shared/src/methods.ts`), the JSON schema (`packages/shared/schemas/`) and the mirrored types in Rust, C# and Python.

## Design rules (mandatory for every UI change)

- **Clean, minimal, calm.** **Not** futuristic: no neon colours, no glow, no glassmorphism/blur, no gradients, no sci-fi fonts.
- It should feel like Linear, Notion or Apple Music: lots of white space and clear typography.
- **Font:** Inter (`@fontsource-variable/inter`, bundled locally, no CDN). Numbers are always tabular (`font-variant-numeric: tabular-nums`, class `.num`).
- **Font sizes:** only 12 / 14 / 16 / 20 / 28 px (`text-xs` … `text-xl`).
- **Colours:** neutral greys and **exactly one** calm accent colour (muted blue `#3B6FD8`). Cove is **dark only** (no light mode, no theme switch); `data-theme="dark"` is always set, also in `index.html`.
- **Spacing** on a 4px grid. **Radius** 8px, cards 12px.
- **Separation** through subtle 1px borders (`border-border`), **no shadows**.
- **Icons:** `lucide-react`, 18px, stroke width 1.75.
- **Animations** only subtle: 150 to 200 ms ease-out. Always respect `prefers-reduced-motion`.
- All raw values live in `apps/desktop/src/styles/tokens.css` (`--cove-*`, the dark values under `[data-theme="dark"]`, accent via `data-accent`). `styles/theme.css` maps them to Tailwind utilities (`bg-surface`, `text-fg-muted`, `border-border`, `bg-accent` …).
- In `theme.css`, Tailwind's default palette, shadows, blur and every font size except the five allowed ones are **switched off**. Classes like `bg-pink-500`, `shadow-lg` or `text-4xl` generate no CSS. Do not switch them back on. If a token is missing, add it to `tokens.css` and `theme.css`.
- **No hard-coded colours in components.** ESLint forbids hex, `rgb()` and `hsl()` literals in `apps/desktop/src`.
- Icon size and stroke width are set globally by `LucideProvider` in `App.tsx`. Don't pass `size` or `strokeWidth` to icons.
- Always use `GameCover` for game artwork. Without an image URL it renders a calm, flat placeholder.
- Every page needs a skeleton loading state (no spinners), an empty state with friendly text (`EmptyState`) and an error state with a retry action.
- Focus states are always visible (`:focus-visible`). Everything must be usable with the keyboard.
- **Contrast WCAG 2.1 AA:** text at least 4.5:1 on every surface it can sit on (`bg`, `bg-sidebar`, `hover`, `active`), input outlines and switch tracks at least 3:1 (`border-input`). Check new tokens with all five accents; `e2e/a11y.e2e.ts` runs axe on every page.
- **TV mode exception:** the TV mode (`src/tv/`, route `/tv`) scales everything by `TV_SCALE` (1.5, CSS `zoom` on its root) so it reads from a distance. Inside it the normal rules apply (same five font sizes, tokens, 4px grid); never add TV-only font sizes.
- Use only 4px-grid spacing utilities (`1`, `2`, `3` …), no half steps (`1.5`, `2.5`). Icons stay 18px, also next to small text.
- Game covers without alt text are decoration (`aria-hidden`); give their link an `aria-label` with the title.
- **UI languages: German and English.** Never write UI text into a component: add it to `src/i18n/de.ts` **and** `src/i18n/en.ts` (same keys; `i18n.test.ts` fails on missing keys or umlauts in English) and read it with `useMessages()` (components) or `messages()` (other code). Texts with values are functions (`(title: string) => …`). Label tables use `localized()`. Formats come from `lib/format.ts` (locale follows the language). The main navigation labels Home, Catalogue, My Library, Downloads, Settings stay English in both languages on purpose.
- Cove's own logo is `components/ui/CoveLogo.tsx` (light square, dark rings, drawn with theme tokens); the app icons are generated from `src-tauri/icons/icon.svg` with `npx tauri icon <1024px png> -o src-tauri/icons` (delete the android/ios folders it creates).
- Store logos (`components/ui/StoreIcon.tsx`, Simple Icons, CC0) are drawn in the current text colour at 18px, never in brand colours.

## Code rules

- **TypeScript:** `strict` plus `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes`. **No `any`**: use `unknown` and type guards. ESLint (`typescript-eslint` strictTypeChecked) must pass without errors.
- **JavaScript (plugins):** ES modules, JSDoc types, ESLint recommended.
- **Rust:** `cargo clippy --all-targets -- -D warnings` (pedantic enabled) without warnings, `cargo fmt`. No `unsafe`. No `unwrap()` outside tests; handle errors as `Result`.
- **C#:** `Nullable` enabled, `TreatWarningsAsErrors`. Everything must be AOT compatible, so no reflection-based serialization: JSON only via the source-generated `RpcJsonContext`. `dotnet format`.
- **Python:** 3.12, `ruff check` + `ruff format`, `mypy --strict`. No `Any` in signatures (ruff `ANN401`).
- **Frontend data access:** The UI gets data **only** through `apps/desktop/src/api/*` (`import { api } from "…/api"`). All core calls go through the typed `call()` / `subscribe()` in `api/transport.ts`. Outside `src/api` (and `src/test`), ESLint forbids imports from `src/mocks`, `@tauri-apps/api/core` and `@tauri-apps/api/event`.
- **No mocks** in the app anymore: everything comes from the Rust core. UI tests use the fake core in `src/test/fakeCore.ts` (Tauri `mockIPC`).
- **Server state:** catalogue data uses TanStack Query (`hooks/useCatalog.ts`, client in `lib/queryClient.ts`). Older views use the small `useQuery` hook; `invalidateQueries()` refreshes both.
- **Catalogue:** sources in fallback order: Cove proxy (`CoveProxyProvider`, URL from `COVE_CATALOG_PROXY_URL` at build time, default in `src-tauri/.cargo/config.toml`), own IGDB keys, own RAWG key, then the local cache. All behind the Rust trait `CatalogProvider` (`src-tauri/src/catalog/`).
- **Catalogue proxy (Worker):** never add generic pass-through routes; every IGDB query is built in the Worker from validated parameters. Secrets only via `wrangler secret put`. Never call `fetch` as a method of another object (workerd throws "Illegal invocation"). Responses must match the `Proxy*` types in `packages/shared`. Deploy guide: `docs/proxy.md`. Credentials only in the OS keyring (`catalog/secrets.rs`), never in SQLite or the UI. Always go through `SecretStore`/`KeyringStore::app()`, never `keyring::Entry` directly: the Secret Service backend starts its own tokio runtime per call and panics on an async worker, so `KeyringStore` runs every call on a plain thread (`off_runtime`). Windows' Credential Manager holds only about 1280 characters per entry, so `KeyringStore` splits longer values (Epic sessions) into parts `<key>#0…` (`chunked`); CI runs `real_keyring_roundtrip` on Windows. Unit tests use `MemoryStore`; after keyring or login changes run `cargo test real_keyring -- --ignored` (real keyring under the separate service `app.cove.desktop.test`, store and itch.io logins through the IPC path; needs the built connectors, e.g. `COVE_CONNECTORS_CMD=binaries/cove-connectors-x86_64-unknown-linux-gnu`). Provider responses are cached in `catalog_cache` (TTL 7 days, stale entries served when offline). Images go through the `cove-img://` scheme and are cached on disk; `ImageRef` rewrites URLs on serialization, so Rust code and the database always hold the original URLs. Steam games use the portrait artwork `library_600x900_2x.jpg` as cover (never the 32×32 icon); when it is missing the image cache falls back to the 1x portrait, the header and finally the header URL from the Steam store API (`images.rs::steam_fallback`). A catalogue match without artwork keeps the existing cover. Steam games also get `header.jpg` as header (wide views like "Weiterspielen"; a missing header goes straight to the store API). Epic covers come from the catalogue `keyImages` (box art, resized via `?h=900&resize=1&w=600`); Epic catalogue requests run eight at a time and are retried on rate limits, because a large library sends hundreds (one after another took minutes and ran into the connectors' 120 s request timeout, so a re-import never finished and titles stayed the app id). Epic imports skip DLCs (`mainGameItem`) and Fab / Unreal Engine assets (catalogue category `asset-format…`; the old marketplace namespace `ue` too). A sync removes store games that are no longer in the account's library unless they are installed, installed by Cove or have a download (`store_games::remove_missing`). A re-import replaces a title that is only the store id (`Upsert::Renamed`, then matched again) and fills missing artwork, never overwrites it. `GameCover kind="header"` falls back to the cover.
- **Recommender sidecar:** started by `src-tauri/src/sidecar.rs` (health check via `system.ping`, request timeout, restart after crash, at most 3 starts per minute) and fed by `src-tauri/src/recommend.rs`. It is stateless: the core sends library signals (`RecommenderLibraryGame`) and catalogue features (`RecommenderGame`) with every request. When it is unavailable, the UI falls back to a simple ranking; never make it a hard dependency. After changing the Python code run `npm run build:recommender -w @cove/desktop`, then `cargo test sidecar_contract` checks the real binary.
- **Plugins (step 7):** guide in `docs/plugins.md`, API types in `packages/shared/src/plugin-api.ts` (versioned, `PLUGIN_API_VERSION`).
  - Plugins run in a dedicated **blob** Web Worker (`src/plugins/worker.ts`, imported with `?worker&inline` so it inherits the CSP) and only talk through messages (`src/plugins/runtime.ts` ↔ `src/plugins/host.ts`). Never give a plugin access to the DOM, Tauri, the network or another plugin.
  - Every API method maps to one permission (`METHOD_PERMISSIONS`). The host checks it; the core re-checks storage, achievements and `library.add` (`Plugins::require`). A new permission needs: the `PluginPermission` type, the Rust enum, `METHOD_PERMISSIONS`, `PERMISSION_LABELS` (UI text) and the docs.
  - Approval state lives in the `plugins` table: a plugin runs only when `granted` covers what `plugin.json` asks for. Files are served via `cove-plugin://localhost/<token>/<path>` (random token per plugin and start; `plugins.rs::resolve_file` refuses other plugins, `..` and symlinks).
  - Plugin data is JSON in `plugin_storage` (limits in `plugins.rs`), plugin achievements in `plugin_achievements`.
  - Example plugins in `/plugins` are tested twice: `node --test` with a fake API, and `src/plugins/host.test.ts` through the real host and runtime.
- **Downloads (step 6):** the engine lives in `src-tauri/src/downloads/` (`DownloadManager`). Only legal sources:
  - Direct links (DRM-free games, mods, patches) and itch.io through its official API (games the user owns, or free ones). The itch.io API key lives **only** in the OS keyring (`itch-api-key`); itch download URLs are resolved right before each start and never stored.
  - Steam games are **not** downloaded by Cove: `downloads_enqueue` hands the install to Steam (`downloads/handoff.rs`) and the status `handedOff` is finished once the local manifest shows the game. Epic games go the same way (Epic Launcher, Heroic on Linux) only when `downloads_enqueue` gets no target, i.e. when the install dialog shows `InstallPreview.launcherOnly`.
  - **GOG games are installed by Cove** (no Galaxy, no gogdl; written from GOG's formats, never port GPL launcher code into this MIT repo). The C# connector builds the plan (`GogContent.cs`, RPC `gog.plan` / `gog.latest`): newest public generation-2 build, depots of the game + owned DLCs in the UI language (else English), 64-bit when there is a choice, files with their chunks, small-file containers, CDN URL templates from `secure_link` (they expire, so the plan is fetched again on every start). Generation-1-only games get a clear error ("über GOG Galaxy installieren"). On Linux, a native game comes as GOG's installer (`.sh` with a zip inside; its `data/noarch` becomes the game folder, `start.sh` the start file).
  - `downloads/gog.rs` downloads the plan inside the download manager (pause, bandwidth limit, progress): each chunk is zlib-compressed and checked with MD5 before and after unpacking and written at their offset. Resume, repair and update are one mechanism: a chunk already on disk with the right MD5 is skipped. `store_installs` (migration 0009) remembers build, platform and installed files; an update removes files the new build dropped. A cancelled first install removes its folder. Started via the primary play task of `goggame-<id>.info` (arguments, working folder; `launcher::plan`), Windows builds on Linux default to Proton.
  - **Epic games are installed by Cove**, written from Epic's formats (no legendary code). The connector (`EpicContent.cs`) does only what needs the session: `epic.installInfo` (signed manifest links, catalogue attributes `ThirdPartyManagedApp`, `CloudSaveFolder`, `OwnershipToken`), `epic.launch` (one-time exchange code, ownership token), `epic.saves` / `epic.saveWriteLinks`. The core parses manifests (binary and old JSON, `downloads/epic/format.rs`) and chunks (SHA-1 checked), downloads chunks in first-use order and assembles files; files already on disk with the right SHA-1 are skipped (resume, repair, update). Anti-cheat files (EasyAntiCheat, BattlEye) or a third-party launcher make a game `launcherOnly`: Cove refuses it and offers the Epic Launcher. DLCs: `epic.installInfo` also lists owned DLCs with a build of their own (`dlcItemList` of the game's catalogue entry, matched with the library records; DLCs that only unlock content have no assets and are left out, the game checks them through the login). They are downloaded into the game folder after the game and kept apart in `store_install_dlcs` (migration 0010: build and files per DLC); an update check also compares the DLC set, and old files are only removed when neither the game nor a DLC still has them (`epic::remove_old`). **DLC choice** (GOG and Epic): `InstallPreview.dlcs` lists `DlcOption`s (sizes per DLC; the preview's own sizes are the game alone; GOG DLCs come from `GogInstallPlan.dlcs`, their sizes from `GogPlan::product_size`). The install dialog's "DLCs auswählen" button opens the list; unticked ids go into `InstallTarget.excludedDlcs` and are stored in `store_dlc_choices` (migration 0011, kept after an uninstall). Downloads and update checks leave them out (`GogPlan::without`, `run_epic`); DLCs bought later are installed. "DLCs ändern" on the game page (overview tab, `features/DlcDialog.tsx`, command `game_set_dlcs`, `DownloadManager::change_dlcs`) stores a new choice and queues an update: ticked DLCs are downloaded, unticked ones removed (old-file cleanup); if nothing could be queued the old choice is restored. **Steam DLCs** can't be chosen from outside Steam (no URL, no API; never write Steam's files): the overview tab lists them (`game_dlcs`, connector `steam.dlcs`: public store API `appdetails` + `IStoreBrowseService/GetItems` for names, at most 200; installed ones from `InstalledDepots`/`dlcappid` in the app manifest) and "In Steam verwalten" opens `steam://nav/games/details/<id>` (`game_manage_dlcs`). **Owned DLCs (GOG/Epic):** the overview tab of every GOG/Epic game lists the DLCs the account owns, installed or not (`game_dlcs`, connectors `gog.dlcs`: GOG product API `expanded_dlcs` ∩ owned ids, no depot in the newest build = `unlockOnly`; `epic.dlcs`: library records in the game's namespace whose catalogue entry has a `mainGameItem`, no assets = `unlockOnly`). Epic's catalogue `bulk/items` takes several ids only as repeated `id=` parameters; a comma-separated list returns an empty object. **itch.io extras:** uploads that are not the game (`ItchUpload.extra`: soundtrack, book …; browser builds are dropped) are offered unticked in the install dialog ("Extras auswählen"); `downloads_add_itch { extras }` queues each as its own download of the same game (`downloads.extra`, migration 0012) into `<game>/Extras` (archives unpacked into a subfolder); the game folder is fixed when queued so extras know where to go, cancelling the game cancels its extras, and extras never become library entries.
  - **Amazon games are installed by Cove** (Prime Gaming; written from Amazon's formats, never port nile's GPL code). Login: Amazon's sign-in page in the webview with the Amazon Games app's device registration (PKCE). `AmazonConnector` derives the PKCE verifier and the device serial from the login `state`, which the core hands back in `expectedReturnTo` for webview logins; the landing page `https://www.amazon.com/?openid…` carries `openid.oa2.authorization_code` (`auth/webview.rs`). The session's `accountId` is the device serial (the library API wants its SHA-256 as `hardwareHash`). Library: `GetEntitlements` (distribution service, `x-amzn-token`, `Content-Encoding: amz-1.0`), store game id = product id. Connector `amazon.download` (entitlement → `GetGameDownload`: `versionId`, `downloadUrl`), `amazon.versions` (`GetLiveVersionIds`, update check), `amazon.sdk` (SDK channel). The core (`downloads/amazon.rs`, `amazon_install.rs`) reads `<downloadUrl>/manifest.proto` (4-byte big-endian header length, protobuf header with the compression, LZMA body as `.xz` or `.lzma`, protobuf manifest: packages → files with path, size, SHA-256/SHAKE-128), downloads `<downloadUrl>/files/<hex hash>` six at a time with the hash checked (files already right are skipped: resume, repair and update) and removes files a new version dropped. Start: `fuel.json` (`Main.Command`, `Args`, `WorkingSubdirOverride`; JSON5-ish) and the SDK variables `FUEL_DIR`, `AMAZON_GAMES_SDK_PATH`, `AMAZON_GAMES_FUEL_ENTITLEMENT_ID`, `…_PRODUCT_SKU`, `…_DISPLAY_NAME` (`store_installs.meta` keeps entitlement and SKU); the SDK files (`FuelSDK_x64.dll`, `AmazonGamesSDK_*`) come once from Amazon's SDK channel into `<app data>/amazon-sdk`. Without a Cove install, Amazon games start through the Amazon Games app on Windows (`amazon-games://play/<id>`). Migration 0016 rebuilds `sources` and `downloads` for the new store (their CHECK constraints; `defer_foreign_keys`, sqlx runs SQLite migrations in a transaction). **Local detection** (`LocalDetection.cs`, no login): the Amazon Games app's uninstall entries under `HKCU\…\Uninstall` (`"Amazon Game Remover.exe" -m Game -p <product id>`, `InstallLocation`, `DisplayName`; Windows) and Heroic's Amazon installs (nile's `installed.json` in `<heroic>/nile_config/nile` or `~/.config/nile`, titles from nile's `library.json`; Linux). The core fills the start file from `fuel.json` (`stores::amazon_executable`); app installs start through the app on Windows, Heroic installs directly (Proton, `fuel.json` arguments, no SDK variables).
  - Epic games Cove installed start directly with the login arguments of Epic's launcher (`epic::launch_args`, exchange code per start, `-epicovt` token file); Epic games from the Epic Launcher keep starting there (`launcher::store_client_plan`). Cloud saves (`downloads/epic/saves.rs`, setting `library.epicCloudSaves`): before a start newer cloud saves replace local ones (backup of the last 5 under `save-backups/`), after a session newer local saves are packed into a manifest + chunks and uploaded (manifest last). Save folders resolve `{AppData}`, `{UserDir}` … inside the Proton/Wine prefix on Linux.
  - **GOG cloud saves** (Galaxy's cloud storage; setting `library.gogCloudSaves`, default on) for GOG games Cove installed (Windows builds; native Linux builds have none). Connector `gog.cloudSaves` (`GogContent.CloudSavesAsync`): the game's own Galaxy client id/secret from the newest build manifest (`clientId`/`clientSecret`), its folders from the public remote config (`remoteConfigUrl`, `content.Windows.cloudStorage`; no locations = Galaxy's default `<?APPLICATION_DATA_LOCAL?>/GOG.com/Galaxy/Applications/<clientId>/Storage/Shared/Files` as `__default`), and a token for that client from the account's refresh token (`without_new_session=1`, the account's own session stays). The core (`downloads/gog_saves.rs`, `gog_cloud.rs`) lists `cloudStorageUrl` (`<userId>/<clientId>`, JSON; 404 = empty), resolves `<?DOCUMENTS?>`, `<?SAVED_GAMES?>`, `<?APPLICATION_DATA_LOCAL(_LOW)?>`, `<?APPLICATION_DATA_ROAMING?>`, `<?INSTALL?>` inside the prefix (unknown variables and `..` are skipped) and compares per folder like Epic: before a start (`game_launch` → `gog_saves_before_launch`, never blocks the start) newer cloud files replace local ones after a backup under `save-backups/<game>/<folder>`, after a session (`after_session`) newer local files are uploaded with `PUT`, `Etag: <md5>` and `X-Object-Meta-LocalLastModified`. Files with the same MD5 are skipped both ways; nothing is deleted. `CloudSaves`' `Debug` hides the token.
  - **Install dialog** (`features/InstallStep.tsx`) before every download Cove installs itself: sizes (`downloads_preview_url`), games folder (dropdown of `library.gameFolders` + native picker `system_pick_folder`), free space / write access / "Program Files" warning (`system_folder_info`, `folders.rs`), "use as default". `downloads_add_url` / `downloads_add_itch` take an `InstallTarget`; the core checks the folder again (`folders::require_install_folder`) and creates `<folder>/<folder_name(title)>` (special characters removed; `lib/folders.ts` mirrors `folder_name` for the preview).
  - **Games folders:** `library.gameFolders`, the default is `downloads.directory` and always first in the list (`db::settings::normalize`). New settings fields need `#[serde(default)]`, else a stored section falls back to defaults.
  - **Steam** never gets a DRM bypass: games start via `steam://rungameid`, installs via `steam://install`, uninstalls via `steam://uninstall` (`game_uninstall`; `DownloadManager::watch_uninstall` waits until the app manifest is gone). With `library.steamSilentStart` (default on) `steam.rs` starts a non-running Steam with `-silent` first and waits until it is ready (signed-in user or web helper settled, at most 90 s).
  - **Move / uninstall:** `game_move` (`mover.rs`: rename on the same drive, else copy + size check + delete, event `game-move-progress`) for manual games; `game_uninstall` deletes only folders of games Cove installed (`LibraryEntry.installedByCove`). `LibraryEntry.launchVia` (`launcher::launch_via`, mirrors `plan`) is shown per game ("Direkt", "Über Steam" …).
  - Parallel range chunks (`transfer.rs`) with resume (finished chunks in `downloads.chunks_done`), one shared bandwidth limit (`limiter.rs`, from the settings), SHA-256 check, unpacking (zip, 7z, tar, tar.gz; unsafe paths are skipped) and executable detection via the scanner. Progress goes out as `download-progress` at most 4 times per second; status changes as `downloads-changed`.
  - All state is in SQLite: interrupted transfers are queued again at start. Pause and cancel must react at once (`Control` watch channel), not only after the next network packet.
  - Tests use `wiremock` servers with real range support (`transfer::tests::RangeServer`); never download from the internet in tests.
- **Store accounts (step 5):** the C# connectors run as a second sidecar (`resolve_connectors()`, errors via `stores::CONNECTOR_ERRORS`). The core keeps the session and passes it per call; the connectors do the token exchange, refresh and store API calls.
  - **Never** see or store passwords. Store sessions (access + refresh token) live **only** in the OS keyring under `store-session:<store>` (`src-tauri/src/stores/`), never in SQLite, logs or files. `StoreSession`'s `Debug` redacts tokens; keep it that way.
  - Steam: system browser + loopback redirect on `127.0.0.1:<random port>/callback` with a `state` check (`src-tauri/src/auth/`), OpenID verified with `check_authentication`. GOG/Epic: own webview window, navigation intercepted (`auth/webview.rs`); Epic also has the "Alternativer Login" with a pasted code.
  - The Steam Web API key lives **only** in the catalogue proxy (Worker secret `STEAM_API_KEY`); the connectors call `/v1/steam/*`.
  - Store endpoints and client ids live in one file: `services/connectors/src/Cove.Connectors/Config/connectors.json`.
  - Connector failures carry `error.data.kind` (`authFailed`, `privateProfile`, `unavailable`, `network`, `invalidRequest`); the core maps them to `AppError` and marks accounts `needsReauth` when a refresh fails.
  - Cove's own achievements are JSON (`src-tauri/resources/cove-achievements.json`, plus `achievements.json` in plugin folders) and evaluated in `src-tauri/src/cove_achievements.rs`.
  - After changing the C# code run `npm run build:connectors -w @cove/desktop` (`build:sidecar` builds both sidecars), then `cargo test sidecar_contract`.
- **Proton (Linux):** Cove runs Windows games with Proton without Steam (`src-tauri/src/proton.rs`, `ProtonManager`). Builds: GE-Proton, downloaded by Cove from GloriousEggroll's GitHub releases (`.tar.gz` + `.sha512sum`, SHA-512 checked, unpacked into `<app data>/proton/<release>`; release list cached in `catalog_cache` as `proton:ge-releases`, fresh for 6 h, an old list is served offline), plus the builds Steam installed (`steam:<folder>`, from `steamapps/common` and `compatibilitytools.d`). Valve's own Proton can only come through Steam. A game picks its build in `LaunchOptions.protonVersion` (column `library_entries.proton_version`, migration 0014; `null` = `library.defaultProton`, default `latest`); `latest` = the newest GE-Proton on the machine. A missing GE-Proton build is installed when the user picks it (`library_update`, `settings_update` → `prepare`) and, at the latest, before the game starts (`game_launch` → `ensure`, the play button shows the progress). Shortly after the start and every 6 h the core installs a new GE-Proton when a game uses `latest` (`check_updates`); older builds installed for `latest` (marker `.cove-latest`) are removed when no game uses them and none runs; builds the user installed are only removed by hand (`proton_remove`, refused while a game uses them). Without umu, Proton starts with `waitforexitandrun`, `STEAM_COMPAT_DATA_PATH` (prefix per game under `compat/`), `STEAM_COMPAT_INSTALL_PATH` and `STEAM_COMPAT_CLIENT_INSTALL_PATH` (Steam's folder or empty). A running install can be cancelled (`proton_cancel`: the download future is dropped at once, leftovers in `.work` removed, phase `cancelled`). Commands `proton_list` / `proton_check` / `proton_install` / `proton_remove` / `proton_cancel`, event `proton-progress`. UI: "Proton-Version" in a game's settings (`features/ProtonPicker.tsx`) and Settings → Proton (`pages/settings/ProtonTab.tsx`, tab only on Linux). Tests use a `wiremock` GitHub with a tiny tar.gz; never download a real Proton in tests.
- **umu-launcher (Linux):** with `library.useUmu` (default on) Proton starts through `umu-run` (Steam Linux Runtime + protonfixes; `src-tauri/src/umu.rs`, managed by `ProtonManager`). The system's `umu-run` (in `PATH`) wins; otherwise Cove downloads the zipapp of the newest GitHub release (`umu-launcher-<v>-zipapp.tar`, SHA-256 from the asset's `digest`; no digest = not installed) into `<app data>/umu/<version>/umu-run` before the first Proton start (id `umu` in `proton_install` / `proton_cancel` / `proton-progress`), keeps it up to date with the Proton check and removes old copies when no game runs. The zipapp needs `python3`. Env: `WINEPREFIX=compat/<game>/pfx` (same Windows folder as without umu, so saves stay), `PROTONPATH`, `GAMEID=umu-<Steam app id>` (Steam id or the ProtonDB title lookup, at most 5 s; else `umu-default`), `STORE=gog|egs|amazon`. umu off, missing, no python3 or a failed install → Proton starts directly. umu is GPL-3.0: only run it, never copy its code.
- **Game options (Linux):** `LaunchOptions.tweaks` (`GameTweaks`, column `library_entries.tweaks` as JSON, migration 0015; unreadable or missing = defaults, DXVK and VKD3D on). `launcher::apply_tweaks` (Linux only, games Cove starts itself; Steam and store clients can't take them): Proton variables `PROTON_USE_WINED3D=1` (DXVK off), `PROTON_NO_D3D12=1` (VKD3D off), `WINE_FULLSCREEN_FSR=1` (FSR without gamescope), and the wrappers `gamemoderun gamescope [-w W -h H] [-f] [-F fsr] -- mangohud <command>`. The `.deb` and `.rpm` packages recommend `mangohud`, `gamemode` and `gamescope` (`bundle.linux.*.recommends` in `tauri.conf.json`; weak dependencies, so a distribution without one still installs Cove); the AppImage brings none. Tools are looked up per launch (`ToolPaths::detect`, `HostEnv.tools`); a switched-on tool that is missing stops the start with a message. Command `system_game_tools` tells the UI what is installed (`features/GameTweaks.tsx` in the game's settings tab, only for `launchVia == "direct"` on Linux). gamescope resolution 160 to 15360 px, checked in `db::library::update`.
- **Save backups:** `src-tauri/src/backups/` (`BackupService`, settings section `backups`: `enabled` (after every session, `lib.rs::after_session`), `directory` (empty = `<app data>/backups`), `keep` 1 to 100). Save locations come from the Ludusavi manifest (MIT, compiled from PCGamingWiki; `manifest.rs`): downloaded with `ETag`/`If-None-Match` at most once a day and turned into a 5 MB `ludusavi/index.json` (about 1.7 s, only saves and config, relative paths refused); a backup reads the index and drops it again. Games are found by Steam/GOG id, else by exact normalized title; `alias` entries lead to their game. `paths.rs` fills the placeholders per context: this Windows user, Cove's Proton prefix (`compat/<game>/pfx/drive_c/users/steamuser`), `~/.wine`, Steam's `steamapps/compatdata/<app>` prefix for Steam games, the Linux user (`<xdgData>`, `<xdgConfig>`); Windows contexts match the manifest's letters in any case (`any_case`, glob ignores its case option for plain parts), links are not followed, a match that is a home, base or AppData folder itself is skipped, more than 20,000 files or 4 GB is refused. Backups: `<folder>/<slug>_<game id>/<time>/files/<original path>` plus `backup.json` (original paths, fingerprint of path/size/time: unchanged = no new backup); restore copies back after backing up the current state (that backup never deletes the one being restored) and never deletes. Commands `game_backups` / `game_backup_now` / `game_backup_restore` (refused while the game runs). UI: `features/SaveBackups.tsx` in the game's settings tab, Settings → Spielstände (`pages/settings/BackupsTab.tsx`). Tests use a tiny YAML on `wiremock`; `COVE_LUDUSAVI_MANIFEST=<file> cargo test real_manifest -- --ignored` checks a downloaded real manifest.
- **Emulators and ROMs:** `src-tauri/src/emulators.rs`, settings section `emulators.romFolders` (`RomFolder`: id, system, path, emulator id or `custom` with `program` and `arguments` containing `{rom}`; checked in `emulators::validate`). `SYSTEMS` lists the consoles with ROM extensions, the RetroArch core and standalone emulators; emulators are found in `PATH`, as Flatpak (`flatpak run <app>`) or in the usual Windows/macOS folders, RetroArch cores in the user's and system core folders. `emulators_scan` adds every ROM (three levels deep; discs listed in an `.m3u` are left out) as a manual game (title without `(USA)`/`[!]` tags), puts it in a collection named after the system and matches the new games with the catalogue in the background (paced). A game whose file lies in a ROM folder starts through its emulator (`launcher::plan` → `emulators::command`, `HostEnv.rom_folders` filled per launch), so game options (MangoHud, gamescope …) and backups apply too. `emulators_systems` tells the UI what is installed. UI: Settings → Emulatoren (`pages/settings/EmulatorsTab.tsx`). Cove ships no emulators, BIOS or ROMs.
- **Prefix tools (Linux):** `src-tauri/src/prefix.rs`, commands `game_prefix_info` (exists, size without following links: `z:` points at `/`, umu adds `pfx/pfx`) and `game_prefix_action` (`open` the `pfx` folder, `winetricks --gui` with `WINEPREFIX` and `WINE`/`WINESERVER` of the game's Proton build; GE-Proton's own copy in `protonfixes/files/bin` (with cabextract, unzip, zenity; that folder first in `PATH`, its `lib` in `LD_LIBRARY_PATH`) wins over the system's, `reset` = delete `compat/<game>`, refused while the game runs). UI: `features/PrefixTools.tsx` in the settings tab of games set to Proton.
- **Time to beat:** IGDB's `game_time_to_beats` (seconds: `hastily` main story, `normally` main + extras, `completely` 100 %), model `TimeToBeat`, command `catalog_time_to_beat { catalogIds }` (at most 5000, only `igdb-` ids). `CatalogProvider::time_to_beat` (default: nothing; IGDB direct; proxy `POST /v1/time-to-beat` with up to 500 ids, an old proxy's 404 hands over to own keys). `CatalogService::time_to_beat` caches each game for 7 days as `v<CACHE_VERSION>:<id>:time-to-beat` ("nothing" too) and never fails for an unreachable catalogue (old entries or fewer games). The Worker caches one entry per id set (cache calls are subrequests, never one per game). UI: `features/TimeToBeat.tsx` on the catalogue and library game pages; My Library's "Spieldauer" filter (`libraryLength` preference, bands by `normally` ?? `hastily` ?? `completely`) loads the times only while it is on.
- **ProtonDB rating (Linux):** `src-tauri/src/protondb.rs`, command `game_proton_rating`, shown as "Linux-Kompatibilität" on the game page's overview tab (`features/ProtonRating.tsx`) only when `detectPlatform() === "linux"`. The core asks ProtonDB's public summaries (`/api/v1/reports/summaries/<steam app id>.json`; 404 or the tier `pending` = no rating) directly, without the proxy or keys. Steam games use their app id; every other game is looked up in the public Steam store search and only taken when the normalized title (`catalog::matching::normalize`) is exactly the same and the hit is an `app`: no rating is better than a wrong one. Both answers, "nothing found" too, are cached in `catalog_cache` (provider `protondb`, keys `protondb:rating:<app id>` and `protondb:steam-app:<normalized title>`, 7 days, stale entries served when the services are down; otherwise `storeUnavailable`). The badge stays neutral (no tier colours). Playwright's browsers report Windows and macOS, so E2E tests of this section set `LINUX_USER_AGENT` (`e2e/app.ts`).
- **Statistics:** `pages/StatsPage.tsx` (route `/stats`, opened by the profile at the bottom of the sidebar and the command palette), command `stats_overview { year }` (`db/stats.rs`, model `PlayStats`). A year counts only `play_sessions` (UTC dates); all time uses the library's `playtimeMinutes` (store playtime included) for totals, top games, genres and stores, while months (last 12), weekdays, streaks and the longest session always come from sessions. Only games in the library count. Charts: `components/ui/BarChart.tsx` (single series, tooltip, hidden table) and `ShareRow`. The chosen period is the `statsRange` preference.
- **Collections:** the user's own groups of library games ("Mit Freunden", "Angefangen"), a game can be in several. Tables `collections` and `collection_games` (migration 0013, `db/collections.rs`); rows point at `games`, not `library_entries`, so a game that leaves the library and comes back is still in its collections (like playtime), while `collections_list` only returns games that are in the library now. Names: whitespace collapsed, 1 to 50 characters, unique without regard to case (compared in Rust, SQLite's `NOCASE` is ASCII only), at most 100 collections; the fake core mirrors these rules. Commands `collections_list` / `_create` / `_rename` / `_delete` / `_set_game`, model `Collection { id, name, gameIds }` (`LibraryEntry` does not know about collections). UI: chips after the store groups in My Library (`LibraryGroup` = a built-in group or `collection:<id>`; a remembered collection that is gone shows everything), rename and delete next to the view switch, and `features/CollectionMenu.tsx`: a small panel with a checkbox per collection and a field for a new one, opened by right-click (or the context-menu key) on a game in grid and list and by the "Sammlungen" button on the game page. No drag and drop.
- **Wishlist and prices:** catalogue games (`igdb-…`) in the `wishlist` table (migration 0017, rows point at `games`; `db::library::upsert_game` stores the game data without a library entry; games in the library, also as a catalogue match, are left out of the list). Prices come from IsThereAnyDeal through the proxy (`POST /v1/prices`: country + up to 50 `{ key, title }`; the Worker looks titles up exactly (`/lookup/id/title/v1`), up to 10 more one by one (`/games/lookup/v1`), then `/games/prices/v3` and `/games/overview/v2`; secret `ITAD_API_KEY`, sent as the `ITAD-API-Key` header; one cache entry per country and title set, 3 h). `src-tauri/src/prices.rs` (`PriceService`) caches each game's answer in `catalog_cache` (provider `prices`, 3 h, stale served offline) and checks the wishlist 2 minutes after the start and every 6 h when `wishlist.priceAlerts` is on (`lib.rs::watch_prices`). Alerts (`decide`): the best price at or below the target (`target`), or a discount with "bei jedem Angebot melden" (`sale`); each deal once (`alerted_price`/`alerted_cut`; a cheaper price or deeper cut is new; a deal that ended resets), as the `price-alert` event (toast) and a desktop notification (`tauri-plugin-notification`, from Rust). Settings section `wishlist` (`country` two letters, default from the system locale; `priceAlerts`), shown on the wishlist page. Commands `wishlist_list` / `_add` / `_remove` / `_update` / `_refresh`, `game_price`. UI: `pages/WishlistPage.tsx` (`/wishlist`, from the catalogue header and the command palette), `features/GamePrices.tsx` (prices and the wishlist button on catalogue pages of games not owned). ITAD's terms: mention them ("Preise von IsThereAnyDeal"), never change prices or links (their affiliate tags stay), don't look affiliated.
- **Controllers and TV mode:** the core reads controllers itself (`src-tauri/src/gamepad.rs`, `gilrs`; the webview's Gamepad API is unreliable in WebKitGTK; Linux builds need `libudev-dev`). `kind_of` tells Xbox, PlayStation, Switch, Steam (Deck/Controller) and generic apart by USB vendor (Sony 054c, Nintendo 057e, Microsoft 045e, Valve 28de), else by name. Buttons become `PadAction`s, face buttons by position (bottom = `confirm`, right = `back`, left = `secondary`, top = `tertiary`), D-pad and left stick repeat while held (`Repeater`), event `gamepad-input { action, kind }`; `gamepads-changed` and `gamepad_list` for the list. Nothing is sent while a game runs or another window is focused; holding Guide/PS/Home brings Cove to the front. The UI: `hooks/useGamepadNavigation.ts` (in `AppShell`, desktop and TV: directions move the focus with `lib/spatialNav.ts`, confirm clicks, back closes the top dialog or goes back, Guide opens the TV mode; other actions go out as the window event `cove-pad`, `onPad`), `html[data-pad-nav]` shows the focus ring. Labels: `lib/padLabels.ts` (Xbox/Steam A B X Y, PlayStation ✕ ○ □ △ drawn as shapes, Switch B A Y X by position; LB/RB, L1/R1, L/R) and `components/ui/PadGlyph.tsx` (`PadGlyph`, `PadHints`), never brand logos. TV mode: `src/tv/` (`TvShell` with sections switched by LB/RB, hint bar; pages Home, Library, Game, Search with an on-screen keyboard, Downloads, Settings), full screen through `window_set_fullscreen`; entered from the sidebar, the command palette, F11 or Guide, and at the start when `general.startInTvMode` is on or `system_tv_hint` says Steam Deck gaming mode / gamescope. E2E tests drive it with `window.__cove.emit("gamepad-input", …)` (`e2e/tv.e2e.ts`).
- **Cached `Game` data:** when its shape changes, bump `CACHE_VERSION` in `src-tauri/src/catalog/mod.rs` and in `services/catalog-proxy/src/cache.ts`.
- **External APIs in tests:** never call real services. Use `wiremock` with the providers' `with_endpoints`/`with_base` constructors and `Endpoints` for the service.
- **New Tauri command:** always change all five places together:
  1. function in `src-tauri/src/commands.rs`
  2. entry in the `cove_handlers!` macro in `lib.rs`
  3. signature in `packages/shared/src/commands.ts` (`CoveCommands`, camelCase arguments)
  4. wrapper in `src/api/*`
  5. handler in the test fake `src/test/fakeCore.ts`

  Also cover the command in `src-tauri/src/ipc_tests.rs` with the real JSON payload.
- **Errors** from Rust are `AppError` (thiserror) and reach the frontend as `{ kind, message }`, there as `CoveError`. The `message` is user-facing text in the UI language (`AppError::user_message`): database, file, keyring and JSON errors get a plain sentence, their technical text only goes to stderr. Never put paths, URLs, OS error codes or stack traces into a message. A new `kind` also goes into `AppErrorKind` in `models.ts`.
  - In the UI always show errors through `errorMessage()` (`stores/toasts.ts`): it passes `CoveError` and `UserFacingError` through and replaces anything else (a programming error) with a generic sentence. Page crashes end in `RouteError`, never in React Router's developer screen.
  - Every text that reaches the UI is written with `tr!("Deutsch", "English", args…)` (`src-tauri/src/i18n.rs`, works like `format!`); log output stays as it is. The language comes from `settings.general.language` (new installs: system language). Tests run German; `i18n::in_english` / `set_thread_english` switch one test thread only. Sidecars get the language via `system.setLanguage` (sent by `Sidecar::call`); C# uses `Texts.T(de, en)`, Python `texts.t(de, en)`.
  - Sidecar processes start with `CREATE_NO_WINDOW` on Windows (no console window).
  - Sidecars get their own temp folder (`$TMP/cove-sidecars`, `sidecar.rs`): a killed PyInstaller onefile binary leaves its `_MEI…` folder (about 160 MB, in RAM where `/tmp` is a tmpfs); unused leftovers older than 10 minutes are removed before each start.
  - Sidecars are never required: when one is missing or crashes, the app keeps working and only its features are off (`SidecarStatus`, shown in Settings → Über Cove). A broken database at start shows a dialog (`report_startup_failure`), not a panic.
- **Performance (step 8):** lists that can hold thousands of games use `VirtualGrid` / `useMainVirtualizer` (TanStack Virtual on `#main`; plain rendering up to `VIRTUALIZE_FROM` items). Images load lazily (`loading="lazy"`, `decoding="async"`). Pages other than Home and Library are lazy routes in `router.tsx`. The core logs `Oberfläche geladen nach … ms` once per start; keep it well under 2 s (currently about 0.6 s with 2500 games).
- **Flatpak:** `packaging/flatpak` (manifest repackaging the release `.deb` on GNOME 51, metainfo), `.github/workflows/flatpak.yml` (bundles for each published release), guide `docs/flatpak.md`. Inside Flatpak (`flatpak::active()`): host programs (Steam, emulators under `/run/host`, Flatpak emulators) start through `flatpak-spawn --host` (`flatpak::route` in `launcher.rs`, `steam::flatpak_start_command`, `emulators::Env`), games started by a store client are followed through the host's `/proc` (`flatpak::host_processes`), the self-updater is off. Every release adds a `<release>` entry to the metainfo and updates the `.deb` URLs/checksums in the manifest.
- **Updates:** `src-tauri/src/updates.rs` (Tauri updater plugin, commands `updates_check` / `updates_install`, event `update-progress`). Releases come from `.github/workflows/release.yml` on a `v*` tag; `latest.json` and signatures are uploaded there. The private signing key lives only in `~/.tauri/cove-updater.key` and the GitHub secret `TAURI_SIGNING_PRIVATE_KEY`; never commit it. `tauri.release.conf.json` switches on `createUpdaterArtifacts` for those builds only.
- **E2E tests:** Playwright in `apps/desktop/e2e/*.e2e.ts`, against a production build of `e2e.html` (`src/test/e2e.ts`: the fake core plus the live behaviour of the Rust core). New main flows get an E2E test; README screenshots come from `COVE_SCREENSHOTS=1 npx playwright test screenshots` (English UI, Linux, invented games with drawn SVG artwork from `e2e/demoGames.ts`; never real games or store artwork).
- **Rust types** in `src-tauri/src/models.rs` mirror `packages/shared/src/models.ts`. `contract_tests.rs` validates serialized values against `models.schema.json`.
- **Database:** SQLite via sqlx with runtime queries (no `query!` macro, so no `DATABASE_URL` needed). Schema changes always come as a **new** file `src-tauri/migrations/NNNN_*.sql`; never edit existing migrations. DB functions get tests using `db::open_in_memory()`.
- **Data types** (Game, LibraryEntry, Achievement, Download, CatalogFilter …) live in `packages/shared/src/models.ts`. After every change regenerate the schema with `npm run schemas -w @cove/shared`. One test checks the schema is up to date, another that mock and fake data match it.
- **State:** Zustand stores live in `apps/desktop/src/stores`; load server data with `useQuery` (`hooks/useQuery.ts`). Call `invalidateQueries()` after mutations.
- Tests live next to the code (TS/JS: `*.test.ts(x)` / `*.test.js`; Rust: `#[cfg(test)]`) or in `tests/` (C#, Python).
- Install dependencies with the package manager (`npm i`, `cargo add`, `uv add`, `dotnet add package`). Never guess versions.
- TypeScript stays pinned to `~6.0` until `typescript-eslint` supports TS 7.

## Commands

Requirements: Node 22+, Rust (stable, with `clippy` and `rustfmt`), .NET SDK 9, `uv`. On Linux also the Tauri system packages (webkit2gtk-4.1, gtk3, libsoup3). AOT publishing additionally needs `clang` and `zlib-devel`.

### Root (TS/JS, all workspaces)
```sh
npm install              # once
npm run dev              # starts the desktop app (Tauri + Vite)
npm run lint             # ESLint + tsc for all workspaces
npm run test             # Vitest (shared, desktop) + node:test (plugins)
npm run check            # lint + test
npm run test:e2e -w @cove/desktop # Playwright (once: npx playwright install chromium in apps/desktop)
npm run schemas -w @cove/shared   # regenerate the JSON schema from models.ts
```

### Desktop: UI + Rust core (`apps/desktop`)
```sh
npm run tauri:dev -w @cove/desktop     # app with hot reload
npm run dev -w @cove/desktop           # frontend only in the browser (http://localhost:1420), window buttons inactive
npm run tauri:build -w @cove/desktop   # release bundle
cd apps/desktop/src-tauri
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo test
```

CI: `.github/workflows/ci.yml` (lint + tests for all five languages, E2E, Rust on Linux and Windows) and `release.yml` (AppImage, .deb, .rpm for Linux x86_64 on `ubuntu-22.04` and ARM64 on `ubuntu-22.04-arm`; MSI, NSIS; .dmg for Apple Silicon on `macos-15` and Intel on `macos-15-intel`; every build native on its own runner; draft release on `v*` tags).

App data (SQLite `cove.db`, Proton prefixes under `compat/`, plugins under `plugins/`) lives in Tauri's app data folder, on Linux `~/.local/share/app.cove.desktop/`. In the browser (`npm run dev -w @cove/desktop`) only the catalogue works; everything from the core shows "only available in the desktop app".

dotnet build

## Working rule

**After every change, run lint and tests for all affected sub-projects before saying "done".**
If something fails, fix it or state the failure explicitly. If a tool is missing locally, say so instead of claiming success.
